# Native action-panel evidence

These PNGs were generated by the real `LauncherApp::view_panel` through
`iced_test`, using Iced's headless wgpu renderer at 2× scale. The fixture has
40 actions in a 320×180 logical-pixel viewport. They are PR evidence, not
cross-machine pixel baselines or screenshots of a GNOME session.

`*-start-wgpu.png` shows the initial selection. `*-scrolled-wgpu.png` shows
the bottom after a mouse-wheel event; the filter stays above the scroll area.
Keyboard reveal is tested separately against the real widget tree and runtime
operations: every selection remains fully visible when traversing down/up,
wrapping at either end and resetting the filter after scrolling.

To reproduce, set `COMPASS_UI_SCREENSHOT_DIR` to a fresh absolute directory:

```sh
COMPASS_UI_SCREENSHOT_DIR=/tmp/new-panel-captures \
  cargo test -j 1 --locked -p compass-ui --lib \
  long_action_panels_keep_a_bounded_scroll_region_below_the_filter
```

The optional capture compares an existing image if one is already present;
ordinary tests do not read these committed images. The filenames include the
renderer selected by Iced. Different renderers/fonts may produce different
pixels. Light-start and dark-scrolled were visually inspected: the field and
final action are visible; partially visible intermediate rows are clipped by
the scroll viewport, not drawn over the filter.

The browser audit in #142 independently fixes the HTML surrogate's bounded
panel. It does not establish native wheel/keyboard behaviour; these widget
tests do. GNOME/Flatpak focus and compositor behaviour remain the VM tier's
responsibility.
