## Findings

- The inspected frames have readable hierarchy, distinct selected rows and no
  obvious clipping. Rofi remains single-line and compact; its titles fit the
  selection band. This is visual inspection, not measured contrast compliance.
- The filtered action panel renders `filter: copy` as a label rather than the
  production editable filter. Update this state before using the surrogate to
  approve action-filter styling or focus affordances.
- The six-state fixture set has no pending daemon query, search failure, launch
  failure, long-label or narrow-viewport case. Add coverage as those states are
  integrated; existing screenshots cannot approve them.
- Fixture application descriptions, grouped sections and management actions
  represent the ported models/design, not proof that the running launcher wires
  every one of them. In particular, favourite management is not implemented by
  merely drawing “Add to Favorites”.

## Themes and the default

The implemented presets are `gnome` (default), `raycast`, `flow` and `rofi`.
They vary geometry and structural flags, not independent colour-theme files.
All use the shared Adwaita-derived light/dark palettes. The running Linux UI
follows the desktop light/dark preference through the Settings portal, falling
back to dark when it cannot obtain a preference.

Thus the current default is GNOME-native-inspired on the main Linux target,
not arbitrary OS theme inheritance. System accent/font inheritance, custom
colour themes and automatic macOS/Windows-native defaults must not be claimed
from these presets. Browser CSS also does not prove Iced renderer fidelity,
portal delivery or native accessibility; those need the native test tiers.
