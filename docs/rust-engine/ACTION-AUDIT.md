# Action audit: every item does something

Issue [#254](https://github.com/tuna-os/compass/issues/254). A launcher whose
commands and actions are listed but do nothing is worse than one that does not
list them, so every item a person can pick is run by a test that fails when it
does nothing visible.

## How the harness works

`crates/compass-ui/src/app/tests/action_audit.rs` does not list the items by
hand. Each test enumerates a registry, runs every item in a fresh launcher over
recording fakes that hold one of everything (an application with a desktop
action, an extension command, quicklinks, snippets, a script, a Rhai script, a
clipboard entry, a window, a workspace, a media player, a tray item, a calculator
record, a store listing, local storage, a token set, an update), and compares
the launcher and the fakes before and after:

- **opens X** / **changes X**: the page, or the state of the page shown.
- **types "…"**: new text in the search bar.
- **says "…"**: a message in the launcher.
- **asks to confirm**, then what confirming did.
- **HUD "…"**: the heads-up display.
- **hides**: the launcher window closes.
- **copies**: a clipboard write.
- **calls engine.X**, **calls clipboard.X**, **calls windows.X**: a request the
  engine, clipboard or window-manager fake recorded (`X` is the fake's record).
- **calls launcher.launched**: the application launcher was asked to start
  something.
- **changes the panel**, **changes root settings**, **changes the theme**,
  **writes compass.json**.

Reads do not count: a launch's ranking record and the queries a view lists
itself with change on nearly every item and would hide a dead one.

An item with none of these is dead and fails its test, and so does a kind of
root row whose Ctrl+B opens no panel at all. The tables below are
generated by the tests and checked against this file, so a new item, or an
item whose effect changes, fails until the inventory here says so. Regenerate
them with:

```sh
COMPASS_UPDATE_ACTION_AUDIT=1 cargo test -p compass-ui action_audit
```

A mutation check: making root search's Copy ID do nothing fails
`every_action_in_a_root_rows_panel_does_something` with the four rows that
offer it.

## What it covers, and what it does not

| Registry | Items | Test |
|---|---|---|
| `compass_core::commands::BUILTIN_COMMANDS`, launched from root search by title | 59 | `every_builtin_command_does_something_from_root_search` |
| The action panel of every view a builtin command opens, over its first row | 85 | `every_action_in_a_builtin_views_panel_does_something` |
| The action panel of each kind of root row (application, builtin command, extension command, quicklink, script, Rhai script, calculator answer, fallback, update) | 55 | `every_action_in_a_root_rows_panel_does_something` |
| The settings view's clickable controls, every sidebar page | 104 | `every_control_in_the_settings_view_does_something` |
| `compass_core::tray::menu_entries`, clicked over D-Bus in a real engine | 6 | `compass_shows_its_own_tray_icon_with_the_cpp_menu_as_the_setting_says` (`crates/compass/tests/engine_end_to_end.rs`) |

Not covered:

- Only the first row of each view is acted on, so actions offered only for
  another kind of row (an image clipboard entry, a pinned record, a running
  application's extra actions) are not in these tables; each view's own tests
  cover them.
- Second-level pages (a store's detail page, a font's preview, the forms
  Create Shortcut, Create Snippet and Create Extension open) are reached and
  counted as effects, but their own panels are not walked.
- The settings grid clicks every 16 by 9 pixels and scrolls eight times, so
  the long provider pages (Commands lists every builtin) are sampled rather
  than walked to the end; every row on them is the same control wired the same
  way. Text fields are typed into rather than clicked, and are not audited.
- Onboarding is another change's (see the report on #254).

## What the audit found, and what changed

- **Open Config File did nothing (#253).** Four ways, each fixed:
  `compass.json` did not exist until something saved a setting, so the engine
  refused it (it is now written first); on GNOME no application claims JSON,
  because the editors claim only `text/plain` (a text file with no opener of
  its own now opens in the text editor); a `Terminal=true` default such as Vim
  was started without a terminal (it now runs in one); and a launch was
  acknowledged before anyone knew whether it started, so the launcher hid with
  nothing opened (the engine now waits to hear, falls back to the `OpenURI`
  portal, which also reaches the host from the Flatpak, and otherwise answers
  with the reason, which the launcher shows).
- **Open Default Config File** wrote `default-config.jsonc` where the
  Flatpak's host editor cannot see it, and `.jsonc` has no MIME type, so it had
  no opener either. It is now written to the cache directory and opened as
  text.
- **Show Log File** had its own copy of the log's path, which before the
  rebrand pointed at the old engine's directory. Both the engine and the
  command now take it from `compass_core::xdg_dirs::log_file`; before the engine
  has written it, the command says so. Showing a file in the file browser was
  also acknowledged before it happened; it now fails with a reason too.
- **The power and media commands' refusals were invisible.** They hide the
  launcher first and then set the refusal as a message inside it, to be seen
  at the next summon. The refusal now also goes to the HUD (19 commands).
- **Search Emojis & Symbols › Reset ranking** does nothing for a glyph never
  picked. That is correct (there is no ranking to reset), so the harness picks
  a glyph first rather than the action changing.
- **The calculator answer at the root had no action panel.** Ctrl+B over it
  opened nothing. It now offers upstream v0.29.0's
  `RootCalculatorSection::actionPanel`: Copy Result, Copy Question And Answer,
  Put answer in search bar and Open Calculator History (the C++'s "Copy
  unformatted answer" has nothing to copy, because fend prints its answers
  unformatted). Over a short list the card now grows to hold the whole panel,
  which had been cut off at the card's edge.
