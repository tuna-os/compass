# ADR-0016: Screen-reader gap — Orca cannot see the Rust launcher

**Status:** Accepted · **Date:** 2026-09-21 · Relates to: #118, #10, ADR-0001 · Re-visits: PLAN.md §6 Phase 7

## Context

The Rust launcher (`iced` 0.14 + `winit` 0.30) has no accessibility tree. Neither
crate depends on `accesskit`, and `Cargo.lock` contains zero occurrences of
`accesskit`, `atspi` or any AT-SPI binding. Orca (GNOME's default screen
reader) therefore sees nothing: not the query field, not the result list, not
the selection, not the action panel. The launcher is bound to **Super+Space** —
intended as the fastest path to anything on the system — and for a blind user
it is currently the one path they cannot use at all.

This was found while answering #4's “watch for” clause; see #118 and #116. Qt's
`QAccessible` gives the C++ engine AT-SPI, so the gap is a **regression the
cutover would ship**, not a pre-existing absence.

## Decision

**Accepted gap for cutover, documented explicitly** — option 4 in #118:

1. Cutover (Phase 7, #10) ships Linux with the Rust engine as default while
   noting the gap plainly in the release notes.
2. The decision is revisited under Phase 9/10 or when Iced gains AccessKit
   integration (the natural home for `winit`-based toolkits). Options 1–3 in
   #118 (wait upstream, contribute upstream, or implement AT-SPI ourselves)
   remain open and are not chosen now because the cost/owner tradeoff is not
   decidable without a survey of Iced's AccessKit effort and a check of what
   the C++ engine actually exposes today.

## Consequences

- One full release cycle with no P0 regressions remains the Phase 7 gate, but
  “P0” does not include a11y until the tree exists — the gap is not a
  regression to be filed after cutover, it is a known absence to be stated
  before.
- If a user has Orca enabled, `doctor` should surface the absence as a
  supported degradation (warning, not failure) rather than silence.
- Any change that adds `accesskit`/`atspi` to the workspace must be accompanied
  by an update to this ADR — the test `a11y_gap_is_documented_not_silent`
  enforces that the absence is recorded, not accidental.
